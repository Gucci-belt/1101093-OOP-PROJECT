สรุป OOP Concepts ในโปรเจค
==========================

1. INHERITANCE (การสืบทอด) - 2 อัน ✓
------------------------------------

1.1 Admin extends User
   - Admin สืบทอดจาก User
   - ได้ fields และ methods จาก User อัตโนมัติ
   - Location: models/Admin.java
   - Code: public class Admin extends User

1.2 Member extends User
   - Member สืบทอดจาก User
   - ได้ fields และ methods จาก User อัตโนมัติ
   - Location: models/Member.java
   - Code: public class Member extends User

2. POLYMORPHISM (พหุรูป) - 2 อัน ✓
-----------------------------------

2.1 UserRepository ใช้ List<User> เก็บทั้ง Member และ Admin
   - List<User> userDatabase สามารถเก็บทั้ง Member และ Admin ได้
   - เพราะ Member และ Admin สืบทอดจาก User
   - Location: repositories/UserRepository.java
   - Code: 
     private final List<User> userDatabase;
     userDatabase.add(new Admin(username, password));
     userDatabase.add(new Member(username, password));

2.2 AuthService รับและคืนค่า User (แต่จริงๆ อาจเป็น Member หรือ Admin)
   - Method login() และ register() รับและคืนค่า User
   - แต่จริงๆ อาจเป็น Member หรือ Admin
   - Location: services/AuthService.java
   - Code:
     public User login(String username, String password)
     public boolean register(String username, String password)
     User newUser = new Member(username, password);

3. ENCAPSULATION (การห่อหุ้ม) - หลายจุด ✓
----------------------------------------

3.1 User Class
   - fields เป็น private (username, password, role)
   - มี public getters (getUsername(), getRole())
   - ไม่มี setter สำหรับ password (ใช้ checkPassword() แทน)
   - Location: models/User.java

3.2 Food Class
   - fields เป็น private final (name, kcal, fat, sugar, sodium)
   - มี public getters เท่านั้น (Immutable Object)
   - Location: models/Food.java

3.3 BMIRecord Class (Value Object - Immutable)
   - fields เป็น private final ทั้งหมด
   - ไม่มี setters (Immutable Object)
   - Location: models/BMIRecord.java

4. ABSTRACTION (การทำให้เป็นนามธรรม) - 2 อัน ✓
-----------------------------------------------

4.1 Interface: FoodFilter
   - กำหนด contract สำหรับการกรองอาหาร
   - Methods: filter(List<Food>), matches(Food)
   - Implementations: LowCalorieFilter, LowFatFilter, LowSugarFilter, LowSodiumFilter, CompositeFilter
   - Location: filters/FoodFilter.java

4.2 Interface: FoodSortStrategy
   - กำหนด contract สำหรับการเรียงลำดับอาหาร
   - Methods: sort(List<Food>), compare(Food, Food)
   - Implementations: CalorieSortStrategy, FatSortStrategy, SugarSortStrategy, SodiumSortStrategy, CompositeSortStrategy
   - Location: sorting/FoodSortStrategy.java

5. COMPOSITION/AGGREGATION (การประกอบ) - 2 อัน ✓
------------------------------------------------

5.1 CartItem มี Food (Composition)
   - CartItem มี Food object เป็นส่วนหนึ่ง
   - ถ้า CartItem ถูกลบ Food ก็หายไปด้วย (composition)
   - Location: models/CartItem.java
   - Code:
     private final Food food;
     public CartItem(String username, Food food)

5.2 CartRepository มี List<CartItem> (Aggregation)
   - CartRepository มี List<CartItem>
   - CartItem สามารถมีอยู่ได้โดยไม่ต้องมี CartRepository (aggregation)
   - Location: repositories/CartRepository.java
   - Code:
     private final List<CartItem> cartDatabase;
     cartDatabase.add(cartItem);

6. DATA STRUCTURES (โครงสร้างข้อมูล) ✓
--------------------------------------

6.1 List (ArrayList)
   - UserRepository: List<User> userDatabase
   - FoodRepository: List<Food> foodDatabase
   - CartRepository: List<CartItem> cartDatabase
   - BMIHistoryRepository: List<BMIRecord> bmiHistoryDatabase
   - FoodTrackingRepository: List<FoodTracking> trackingDatabase

6.2 Map (HashMap)
   - UserRepository: Map<String, String> passwordStorage (เก็บ password แยก)
   - Controllers: Map<String, Object> สำหรับ Response

7. DESIGN PATTERNS ✓
--------------------

7.1 Strategy Pattern
   - FoodFilter Interface + Concrete Filters (LowCalorieFilter, LowFatFilter, etc.)
   - FoodSortStrategy Interface + Concrete Strategies (CalorieSortStrategy, FatSortStrategy, etc.)
   - Location: filters/, sorting/

7.2 Composite Pattern
   - CompositeFilter - รวมหลาย Filter เข้าด้วยกัน
   - CompositeSortStrategy - รวมหลาย Sort Strategy เข้าด้วยกัน
   - Location: filters/CompositeFilter.java, sorting/CompositeSortStrategy.java

7.3 Repository Pattern
   - UserRepository, FoodRepository, CartRepository, etc.
   - แยกการเข้าถึงข้อมูลออกจาก Business Logic
   - Location: repositories/

7.4 Value Object Pattern
   - BMIRecord - Immutable Object
   - Food - Immutable Object
   - Location: models/BMIRecord.java, models/Food.java

รายละเอียดเพิ่มเติม:
-------------------

INHERITANCE:
- User เป็น base class
- Admin และ Member สืบทอดจาก User
- ใช้คำสั่ง "extends User"
- ใช้ super() เพื่อเรียก constructor ของ parent class

POLYMORPHISM:
- ใช้ List<User> เพื่อเก็บทั้ง Member และ Admin
- Method ที่รับ User สามารถรับ Member หรือ Admin ได้
- Runtime polymorphism: เรียก method ตาม object จริง

ENCAPSULATION:
- ใช้ private fields เพื่อซ่อนข้อมูล
- ใช้ public methods เพื่อเข้าถึงข้อมูล
- ไม่เปิดเผยข้อมูลภายในโดยตรง

ABSTRACTION (Interface):
- ใช้ Interface เพื่อกำหนด contract
- Classes ที่ implement Interface ต้อง implement methods ทั้งหมด
- ช่วยให้โค้ดยืดหยุ่นและขยายได้ง่าย

COMPOSITION:
- CartItem มี Food (strong relationship)
- Food เป็นส่วนหนึ่งของ CartItem
- ถ้า CartItem ถูกลบ Food ก็หายไปด้วย

AGGREGATION:
- CartRepository มี List<CartItem> (weak relationship)
- CartItem สามารถมีอยู่ได้โดยไม่ต้องมี CartRepository
- CartItem เป็น independent object

DATA STRUCTURES:
- List: ใช้เก็บลำดับของ objects (ArrayList)
- Map: ใช้เก็บ key-value pairs (HashMap)

DESIGN PATTERNS:
- Strategy Pattern: แยกอัลกอริทึมออกมาเป็น classes แยกกัน
- Composite Pattern: รวม objects หลายตัวเข้าด้วยกัน
- Repository Pattern: แยกการเข้าถึงข้อมูลออกจาก Business Logic
- Value Object Pattern: สร้าง Immutable Objects
